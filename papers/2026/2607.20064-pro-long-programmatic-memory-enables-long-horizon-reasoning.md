# PRO-LONG: Programmatic Memory Enables Long-Horizon Reasoning

## Metadata
- arXiv ID: 2607.20064
- Authors: Alexis Fox, Junlin Wang, Paul Rosu, Bhuwan Dhingra
- Published: 2026-07-22
- arXiv link: https://arxiv.org/abs/2607.20064v2
- PDF link: https://arxiv.org/pdf/2607.20064v2
- Code/repo: https://github.com/alexisfox7/PRO-LONG

## Why this matters
Long-horizon reasoning is the core bottleneck for LLM agents on tasks requiring hundreds or thousands of steps with evolving state. Existing approaches either cram everything into context (expensive, degrades with length) or compress/summarize history (lossy, irreversible). PRO-LONG shows that a trivially simple alternative — append every observation verbatim to a log file and let the agent grep/Python its way through it — outperforms elaborate specialized harnesses at 4-6x lower token cost. Practical use cases: game-playing agents, autonomous research assistants, long-running coding agents, any agentic loop where you cannot predict which past observations will be relevant later.

## Technical idea
PRO-LONG wraps a standard coding agent (Codex CLI or Claude Code CLI) with a minimal context management layer. The 'write' operation is a dumb append: after every action, the harness appends a structured entry to logs.txt containing a header (action number, level, attempt, score), the agent's plan summary, the action taken, and the resulting 64x64 board state as ASCII. The 'read' operation is entirely up to the agent: it uses its standard shell tools (cat, grep, python3, sed, awk) to search and analyze the log programmatically. No summarization, no embeddings, no vector DB, no subagents. The agent can run regex searches to find score transitions, write Python scripts to replay actions and verify a coded game model, or do BFS over parsed board states. The system prompt is ~30 lines. The key insight is that coding agents are natively good at structured search over text files, so tractability of retrieval over 100k+ line logs is not a problem — the agent just writes a grep or a Python parser.

## Implementation plan
1. ENVIRONMENT SETUP: Clone https://github.com/alexisfox7/PRO-LONG, create a Python 3.12 venv, run 'pip install -e .', and create a .env file with ARC_API_KEY, ANTHROPIC_API_KEY, and OPENAI_API_KEY. You need Docker installed.

2. BUILD DOCKER SANDBOXES: Run the four docker build commands from the README to build codex-sandbox, openai-proxy, claude-sandbox, and anthropic-proxy images. These provide isolated Python 3 environments with only stdlib available.

3. UNDERSTAND THE LOG FORMAT: Read prolong_agent/agent/game_state.py to understand how board states are formatted as 64x64 hex-character grids using the 16-color ASCII map. Understand the log entry structure: header line with [Action N | Level L | Attempt A | Score S], agent plan summary, action taken, then [POST-ACTION BOARD STATE] followed by the grid.

4. UNDERSTAND THE PROMPT: Read prolong_agent/agent/prompts.py. The system prompt (~30 lines) tells the agent: logs.txt is the game log, parse it programmatically, write actions to actions.json as a JSON list. The user prompt on first call says 'Read ./logs.txt' and on subsequent calls says 'Read ./logs.txt (last N actions)'. This is the entire harness — internalize it.

5. RUN A SINGLE GAME BASELINE (no-log): Run 'prolong-swarm --game ft09 --log-window -1 --max-actions 100' to establish a no-log baseline on a simple game. ft09 (recoloring boxes) typically completes in 100-200 actions. Check evaluation_results/ for the output score.

6. RUN PRO-LONG ON THE SAME GAME: Run 'prolong-swarm --game ft09 --max-actions 100' (default is full log). Compare the score to step 5. For ft09 both should be similar since the current board is sufficient — this is the expected result per Figure 4 in the paper.

7. RUN PRO-LONG ON A LONG-HORIZON GAME: Run 'prolong-swarm --game m0r0 --max-actions 500' and compare with '--log-window -1'. Per the paper, PRO-LONG scores 100% on all 5 runs vs 34.2% for no-log on m0r0. This is where the gains are clearest.

8. REPRODUCE THE TOOL LADDER ABLATION (Table 1): Run three variants on a small game set: (a) read-only tools only by modifying the sandbox Dockerfile to remove grep/python from PATH, (b) read + grep, (c) full toolset. The paper shows read-only=23.1%, +grep=27.2%, +python=38.3%, +write/edit=41.2% on GPT-5.5.

9. REPRODUCE WORKSPACE PERSISTENCE ABLATION (Table 2): Run 'prolong-swarm --suite all --workspace stateless' vs default persistent workspace for both PRO-LONG and no-log. PRO-LONG should be nearly unaffected (~0.5pp drop) while no-log drops ~4pp, confirming PRO-LONG does not rely on written notes.

10. RUN FULL 25-GAME SUITE: Run 'prolong-swarm --suite all --max-actions 500 --backend codex -m gpt-5.5' for 5 independent runs (each run is a fresh session). Compute pass@1 by averaging per-game means across games, and best@k by taking the max per game over k runs. Compare against the no-log baseline.

11. TOKEN COST ANALYSIS: The harness reports billed tokens per game. Use Equation 2/3 from Appendix A to weight input, output, cache_read, and cache_write tokens by their relative prices. Compare your billed token counts against WorldModeler (Codex) or Schema (Claude Code) published numbers.

12. EXAMINE LOGS FOR QUALITATIVE BEHAVIOR: For m0r0 or g50t runs, inspect the logs in evaluation_results/ to find examples of the agent writing BFS scripts, building transition functions, or running regress.py to verify its game model against logged boards. These qualitative patterns are described in Section 3.3.

## Dependencies
Runtime: Python 3.12, Docker (for sandboxed agent execution). Python packages: installed via 'pip install -e .' from pyproject.toml (arc_agi engine v0.9.7 pinned, plus standard agent orchestration deps). LLM APIs: OpenAI API (GPT-5.5 / Codex CLI) and/or Anthropic API (Claude Opus 4.6, Claude Opus 4.8, Fable 5 / Claude Code CLI). No local models required — all inference is API-based. Compute: No GPU needed locally. API costs: ~5-7M billed tokens per game at 500 actions for PRO-LONG on Codex; ~8-10M for Claude Code. Full 25-game pass@1 run ≈ $50-200 depending on model. ARC-AGI-3 API key required (from arcprize.org). Data: No training data needed; ARC-AGI-3 public game set (25 games) is accessed via the official API.

## Limitations / risks
1. ARC-AGI-3 API access is required and may have rate limits or costs beyond the LLM tokens themselves. 2. Log files can exceed 320,000 lines for long games (g50t is mentioned explicitly) — at some scale even grep becomes slow, though the paper claims tractability at 100k+ lines. 3. High variance across runs: pass@1 for GPT-5.5 is 41.2% but best@5 is 60.1%, a 19pp gap. A single run is unreliable for evaluation; reproducing paper numbers requires 5 runs per game which multiplies cost. 4. Model availability: Fable 5, GPT-5.5, Claude Opus 4.6/4.8 are frontier models that may change pricing, behavior, or availability. Results are tightly coupled to specific model versions. 5. The no-log baseline already has access to a persistent workspace and can write notes — it is stronger than typical continual learning baselines, so gains over truly minimal baselines would be even larger but comparison to published harnesses would be less meaningful. 6. Games where the current board fully specifies dynamics (e.g. ft09, cd82) show little benefit from PRO-LONG — the method's value is concentrated in games requiring temporal memory. 7. Docker setup complexity: four images need to be built and networking (egress proxy) must be configured correctly for the sandbox to have API access while remaining isolated.

## Next steps
1. Reinforcement learning integration: Train the agent with RL to close the gap between pass@1 and best@k, since the high variance suggests many games are solvable but not consistently solved. 2. Log compression with lossless indexing: Add a lightweight index (e.g. action number → byte offset) to make log seeks O(1) without summarization, enabling even faster programmatic reads on very long logs. 3. Co-training models with the harness: Fine-tune a base model on PRO-LONG trajectories to make programmatic log analysis a first-class behavior rather than an emergent one. 4. Generalization to other long-horizon benchmarks: Apply PRO-LONG directly to NetHack (BALROG) and other continual learning benchmarks; the harness is game-agnostic. 5. Hybrid memory: Study interactions between the append-only log and scratchpad notes or compressed summaries — Table 2 shows notes add little currently, but combining them intelligently might help in constrained-context settings. 6. Structured log format improvements: Experiment with richer log schemas (e.g. diff-only board states to reduce log size, or tagging score transitions explicitly) to make programmatic search even more efficient. 7. Multi-game transfer: Currently each run is fully independent with no cross-game information sharing; explore whether a meta-log or game-type classifier could bootstrap strategy across structurally similar games.
